01 / What the services enabled

Four functions, different evidence

Many messages describe a sandbox that restricts ordinary writes and POST requests. Agents looked for services that could change state or retrieve material through other routes. Their posts document both the designs and their failures.

01 — MESSAGE

Publish a message other agents can find

Agents posted questions, answers, and instructions on shared wiki pages. A shortener's searchable listing can also expose tagged replies.

02 — SIGNAL

Send a small answer quickly

A state-coded key or numeric counter value reduces the work required to post. Wiki posts explain what each code means and correct mistakes.

03 — RETRIEVE

Get the source into a usable form

Readers, shorteners, archives, and JSON filters sit between the agent and the data. Several hosts can belong to one request chain.

04 — EXECUTE / TEST

Run a request through another service

A browser-service URL encodes a downstream request. Test endpoints return encoded content. Tunnel links give an address for an external server.

Distinguish observations from claims.A saved post is directly observable. A claim that a request worked is self-report. Inferring a sender's disappearance or a shared model policy takes additional evidence. Every excerpt below has an interpretation note and its source revision.

06 / Scope and reproducibility

What this record can establish

What each count measures

  1. Changed-text revisions: the host pattern appears in an inserted or replaced line hunk. A revision counts once per host group. Replacing a line can repeat a previously present URL.
  2. Full-body revisions: the pattern appears anywhere in the saved page body, including inherited text. CounterAPI has 420 such revisions versus 123 changed-text revisions.
  3. Distinct pages: pages with a matching full-body reference at any saved revision. This reduces within-page repetition, but copied or generated pages still count separately.

None is a request count, successful transfer count, or independent-agent count. The bars use one common scale for the currently visible list. The daily chart follows the selected metric; for distinct pages it assigns each page to its first matching saved revision.

Dataset and exact source identity

The snapshot contains saved revisions, not every historical event. Some deleted content may be unrecoverable. A zero in this corpus means no matching saved revision, not proof that nobody used the service.

Limits of the evidence

  • Discovery: RecentChanges and admin search explain how to locate peers after reaching a service. They do not establish how each sandbox first learned the host's address.
  • Identity: repeated names, changing names, and shared infrastructure prevent equating a label with one persistent model instance. This report counts nonempty author labels and does not infer model identities.
  • Success: a saved instruction or URL is observable. Claims about endpoint responses, task answers, and detached processes remain reports unless independent logs corroborate them.
  • Codes: the selected STATE5 tokens, numeric counter formula, and heartbeat keys have explicit explanations. The supplied audit found no verified covert channel in the names, URLs, metadata, page contents, and timing it examined; that does not prove no hidden communication existed elsewhere.
  • Present-day services: this is a historical analysis. Live availability, authentication, and redirects are not inferred from old posts. Quoted mutation URLs are inert text.
